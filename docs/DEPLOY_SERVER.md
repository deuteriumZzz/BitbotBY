# BitbotBY на сервере (VPS)

На своём компьютере ничего этого не нужно: там бот запускается ярлыком BitbotBY.
Эта инструкция — для запуска на удалённом сервере, чтобы бот работал круглосуточно,
а приложение открывалось по адресу `https://ваш-домен/app/` и в Telegram.

## Что понадобится

1. **Сервер** с Linux (Ubuntu 22.04 или новее), 2 ГБ памяти и больше.
2. **Домен** (например `bot.example.com`), у которого A-запись указывает на IP сервера.
3. На сервере открыты порты **80 и 443** (через них Caddy получает сертификат HTTPS).
4. **Docker** на сервере: <https://docs.docker.com/engine/install/ubuntu/>.
5. **Бот в Telegram**: в @BotFather отправьте `/newbot` и сохраните токен — он понадобится один раз.

## Запуск — одна команда

```bash
git clone <адрес вашего репозитория> bitbotby && cd bitbotby
python3 launcher/launch.py server --domain=bot.example.com
```

Команда сама:

- создаёт `.server/server.env` с мастер-ключом хранилища и ключом панели (права 600, в git и в образ Docker не попадает);
- собирает и запускает бота, дашборд, Redis и Caddy (первая сборка — 5–15 минут), Caddy сам получает сертификат HTTPS;
- спрашивает токен бота (ввод не показывается) и просит отправить боту 6-значный код — так она находит ваш чат;
- сохраняет токен и чат в зашифрованное хранилище и перезапускает бота.

Дальше откройте `https://bot.example.com/app/` и войдите кодом, который пришлёт ваш бот.
В самом боте появится кнопка «Терминал» — это то же приложение внутри Telegram.
Ключи Bybit и AI вводите в приложении: **Настройки → Подключения**.

Бот стартует в **Paper** (сделки виртуальные). Переход на реальные деньги — в приложении,
с кодовым словом и подтверждением, как и на компьютере.

## Как здесь устроена безопасность

- **Ключи сервисов (Bybit, AI, Telegram) — только в зашифрованном хранилище** (`data/`). Файл `.env` серверу не нужен
  и не читается. В `.server/server.env` лежат только мастер-ключ хранилища, ключ панели и домен.
- **Вход — те же способы, что и раньше:** код в Telegram в браузере и подпись Telegram в MiniApp. Пустить может только
  владелец бота (ваш chat id). Одноразовой ссылки лаунчера и `/app` из Telegram на сервере нет — они только для
  своего компьютера.
- **Без входа ничего не видно:** данные приложения требуют входа или ключа панели с первой минуты, даже пока Telegram
  ещё не подключён.
- **Наружу открыт только Caddy (HTTPS).** Дашборд, Redis и бот — во внутренней сети Docker. Служебные `/metrics`
  (баланс, P&L) и `/webhook/*` снаружи отвечают 404.

## Повседневное

| Что | Команда |
|---|---|
| Обновить после `git pull` | `python3 launcher/launch.py server` |
| Последние логи | `python3 launcher/launch.py server-logs` |
| Остановить | `python3 launcher/launch.py server-stop` |

Данные (`data/`, `models/`, `logs/`) и ключи при остановке и обновлении сохраняются.

## Обязательно сохраните

**`.server/server.env`** — в нём мастер-ключ хранилища. Без него сохранённые ключи не прочитать.
Держите копию в надёжном месте (не в репозитории), вместе с резервной копией папки `data/`.

## Если что-то пошло не так

- **Сертификат не выдаётся** — проверьте, что домен указывает на этот сервер и порты 80/443 открыты; логи Caddy:
  `python3 launcher/launch.py server-logs`.
- **«Токен не подошёл»** — скопируйте токен из @BotFather заново и запустите команду ещё раз.
- **«Этого бота уже опрашивает другая программа»** — тот же бот запущен где-то ещё (например, на компьютере).
  Остановите его там или заведите на сервере отдельного бота.
- **Код не пришёл в бота** — откройте именно своего бота, нажмите «Start» и отправьте код ещё раз, запустив команду снова.

Старый `docker-compose.yml` с nginx читает `.env` — для сервера используйте `docker-compose.server.yml`
(его и запускает команда выше).
