# Путь решения

1. **Сканер** собирает снимки рынка; **качество данных** присваивает статус каждому (`VALID`… `UNAVAILABLE`); опциональный gate (`DATA_QUALITY_GATE`) блокирует вход по плохим данным.
2. **SignalCombiner** по режиму (`local` / `ai` / `dqn` / `hybrid`) собирает рекомендации. Режимы с SAC без загруженной и **допущенной реестром** модели не торгуют (`mode_readiness` показывает причину в Telegram и в приложении).
3. **Hybrid:** согласие AI и SAC с весами по режиму рынка; SAC hold = вето; SAC solo — только при уверенности ≥ 0.80; Chronos/TimesFM — мягкий модификатор. Эталон правила (`decision_engine.current`) сверен с боевым кодом на 350 комбинациях; ещё четыре стратегии объединения считаются в тени.
4. **Контекстные фильтры:** контекст рынка, сентимент, прямые контекстные сигналы.
5. **Исполнитель:** защиты (слоты, кулдаун, корреляция, ликвидность, экспозиция портфеля, размер по Kelly/риску), вход рыночным ордером, SL/TP на бирже (`reduceOnly`), сопровождение `PositionMonitor`.
6. **Единый Risk Gate** вычисляет вердикт для фактического входа и пишет `risk_gate_shadow` — пока без применения.
7. **Журнал:** каждое решение (`signals`), попытка исполнения (`execution`), отказ (`rejections`), исход (`outcome`) связаны по `decision_id`; цикл — по `trace_id`.

## Что объясняет решение
`python -m bitbot.domain.decision.explain <decision_id>`, Telegram `/audit <decision_id>`: участники и природа их confidence, стадии уверенности, конфликты, группы и избыточные каналы, итог исполнения и исход.

## Оркестратор L1–L4 (спроектирован, не подключён)
`backend/bitbot/ai/orchestrator.py`: L1 Signal Intelligence + Meta-Model → L2 + SAC/прогноз → L3 + LLM/RAG → L4 перепроверка конфликта; безопасный отказ при плохих данных; бюджет времени; ранняя остановка, если решение уже уверенное. Сегодня маршрутизацию выполняет `combine()` по режиму; оркестратор заменит её, когда появятся Meta-Model и ≥ 2 тяжёлых компонента.

## Инварианты
Модели только предлагают; решение принимает Decision Engine; допустимость проверяет независимый Risk Engine; исполняет Execution. Отсутствие ответа никогда не подтверждает сделку. Закрывающие ордера не блокируются никакими защитами входа.
