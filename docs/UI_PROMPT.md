## 1. Что за продукт (контекст, не выдумывай другое)

BitbotBY — AI-гибридный бот для **Bybit** (futures linear + spot), Python/FastAPI/ccxt, Redis, SQLite, Prometheus/Grafana, управление через Telegram. Цикл: скан рынка (bluechip 20 / altcoin 100 / meme 200) → prescore топ-30 → 13 сигналов рыночного контекста → 16 стратегий + AI + SAC [+Chronos] → composite score → guards (macro blackout, correlation, liquidity, Kelly, drawdown scaling, Almgren-Chriss, dynamic leverage) → ордер с SL/TP → `PositionMonitor` каждые 5 с (trailing, partial TP). Два режима цикла: **полный скан** (есть свободные слоты) и **мониторинг** (все слоты заняты). Режимы работы: Paper / Live. Профили рынка: Bluechip / Altcoin / Meme. Режимы сигнала: Local / AI / SAC(dqn) / Hybrid (+Chronos). Риск-профили: conservative / moderate / aggressive.

## 2. Архитектура

**Бэкенд — расширяем существующий `src/dashboard`, не создаём второй сервер:**
- Управляющие эндпоинты, 1-в-1 повторяющие действия Telegram-бота (пауза/возобновление, closeall, режим, профиль рынка, риск-профиль, плечо, слоты, часы торговли, список символов, AI-провайдер, уведомления, таймаут подтверждения, запуск обучения SAC / бэктеста). **Не дублируй логику** — вынеси общую часть из `telegram_commander.py` в сервисный слой, который вызывают и бот, и API.
- **WebSocket `/ws`** — стрим: цены открытых/наблюдаемых монет, позиции и PnL, события цикла (скан → prescore → сигнал → решение → ордер → закрытие), статус guards, задержка до Bybit. Источник — Redis pub/sub + опрос `PositionMonitor`; если события в коде ещё не публикуются — добавь минимальную публикацию.
- **Авторизация:** (а) Telegram MiniApp — серверная HMAC-проверка `initData` + белый список владельца (как в `telegram_commander`), (б) Desktop — токен, выдаваемый при первом запуске; basic auth в nginx остаётся только для старого `/` и Grafana. HTTPS обязателен для MiniApp.
- **Ключи вводятся в UI** — все, что сейчас лежат в `.env`: Bybit (+testnet), AI-провайдеры (Groq, Gemini, Claude, DeepSeek, OpenAI, OpenRouter, NVIDIA — каждый с выбором модели), Telegram-бот и chat_id, NewsAPI, Finnhub, Glassnode, Reddit, Twitter/twscrape, Telethon, PumpPortal, пароли Redis/дашборда, секрет вебхука Alertmanager, PIN для Live. Правила:
  1. Поле **write-only**: API принимает ключ, но никогда не отдаёт его обратно. `GET` возвращает только `{set, last4, status, checked_at}`.
  2. Хранение на сервере **в зашифрованном виде** (libsodium/Fernet). Мастер-ключ живёт вне БД (env/Docker secret). В Tauri-сборке с локальным ботом — системная связка ключей ОС.
  3. Перед сохранением — **проверочный вызов** к сервису. Для Bybit — баланс и права ключа: ключ с правом вывода средств отклонять или требовать явного подтверждения. В ответ — понятная причина отказа («402 — нет баланса», «429 — квота исчерпана»).
  4. После сохранения клиент сервиса пересоздаётся **без перезапуска бота**.
  5. Каждое изменение пишется в audit-лог — без значения ключа. Ключи не попадают в логи, ответы об ошибках, Prometheus, Redis-кэш и Telegram.
  6. `.env` остаётся источником начальных значений и запасным путём, если UI недоступен.
- **Каждый параметр бота регулируется из UI.** Не верстай ~90 полей вручную. Сделай один декларативный реестр настроек: перенеси поля `config.py` в pydantic-settings модель с метаданными — группа, подпись по-русски, подсказка, тип, min/max/шаг, единица, `secret`, `hot` (применяется сразу) или `restart`, `danger`.
  - `GET /api/config/schema` отдаёт схему, `GET/PATCH /api/config` — значения. UI рендерит форму по схеме, поэтому новая переменная в коде сама появляется в интерфейсе.
  - Приоритет значений: изменение из UI (Redis/SQLite) > `.env` > значение по умолчанию.
  - `hot`-параметры применяются через `runtime_config` — там уже ~30 ключей в Redis, расширь список. Остальные помечаются «после перезапуска», и UI предлагает перезапуск через `supervisor.py`; открытые позиции при этом не трогаются.
  - Серверная валидация повторяет `Config.validate()`: например, `DAILY_LOSS_LIMIT ≤ MAX_DRAWDOWN_PERCENT`, `LEVERAGE_MIN ≤ LEVERAGE_MAX`, `DQN_WEIGHT + AI_WEIGHT = 1`. Невалидный `PATCH` отклоняется целиком.
  - Известная проблема: `MAX_DRAWDOWN_PERCENT` в коде один, но используется дважды — для снижения плеча в `order_executor.py` и для полной остановки в `trading_bot.py`. В `.env.example` он описан два раза с разными значениями (0.15 и 0.20), действует последнее. Раздели на два параметра.
- **Безопасность действий:** все опасные команды (Panic Close, смена Paper→Live, рост плеча) — идемпотентные, с серверным подтверждением, пишутся в audit-лог (кто/когда/что). Panic Close = существующий `/closeall` + отмена ордеров; в UI — hold-to-confirm (удержание 1 с) и отдельная подпись режима.

**Фронтенд (одна кодовая база):** Vite + React + TypeScript SPA (Next.js не нужен — Tauri требует статику), TailwindCSS + shadcn/ui, Zustand, `motion/react`, `lightweight-charts` для свечей, Recharts для остальных графиков, `@telegram-apps/sdk` (MiniApp), `@tauri-apps/api` (Desktop). Структура:

## 3. UX: «плоский интерфейс», но без потери функций

Три вкладки — **Терминал**, **Боты**, **Настройки** — максимум один уровень вложенности (раскрывающиеся секции, не вложенные меню). Везде подсказки `[?]` простым языком (без «Kelly», «CVaR» — вместо них «Размер сделки по статистике»; термин — во всплывающей подсказке).

**Sticky TopBar (всегда видна):** Master Switch (Бот активен / на паузе = `/pause`·`/resume`), **PANIC CLOSE**, бейдж `PAPER` / `LIVE` (LIVE — заметный, красный контур), статус связи `Bybit: 18ms`, индикатор режима цикла: 🔍 Сканирую / 👁 Слежу за позициями / ⏸ Пауза / ⛔ Остановлен guard’ом (с причиной: drawdown halt, ATR spike, macro blackout, circuit breaker, дневной лимит убытков).

### Вкладка 1 — Терминал
- **P&L-сводка:** realized 24ч / 7д / 30д / всё время ($ и %) + unrealized; **чистый профит после комиссий** (в таблице `trades` есть `commission`). Баланс, пиковый баланс, текущая просадка.
- **Эффективность:** Win Rate, Profit Factor, R:R, средний выигрыш/проигрыш, Max Drawdown. Sharpe показывать только если сделок достаточно, иначе «мало данных».
- **P&L-календарь (heatmap)** по дням.
- **График** (lightweight-charts): свечи выбранной монеты, маркеры входа/выхода из `trades`, живые линии SL/TP/trailing.
- **Позиции:** карточка = монета, сторона, плечо, вход/текущая, PnL, расстояние до SL/TP, стратегия + уверенность, «почему открыта» (поле `context_flags`). 1-tap: `Закрыть по рынку`, `Изм. SL/TP`, `Trailing`, `Частичная фиксация`.
- **Лента событий** человеческим языком: «Нашёл SOL: RSI перепродан, funding перегрет в шорт → LONG, уверенность 0.71», «Пропустил DOGE: коррелирует с открытой SOL», «Закрыл по trailing +1.8%».
- **Исполнение:** задержка ордера, slippage (оценка Almgren-Chriss vs факт), комиссии.
- **Честность метрик (обязательно):** блок «Live vs Backtest» (`backtest_live_divergence.py`, `paper_alpha_report.py`) и статус kill-switch стратегий (live-alpha). Если у стратегии нет статистически значимого edge — UI так и пишет, без маркетинговой подачи. Не рисуй «красивые» цифры, которых нет в данных.

### Вкладка 2 — Боты
- **Умные пресеты риска** — карточки, маппятся на существующие `risk:conservative|moderate|aggressive`; в карточке реальные значения порогов confidence, плеча, слотов, ширины SL/TP. Никаких «сеток» — их в боте нет.
- Профиль рынка (Bluechip / Altcoin / Meme) + авто-сезон (`toggle_season_mode`, SeasonDetector); режим сигнала (Local / AI / SAC / Hybrid, переключатель Chronos); Spot/Futures; число слотов и символов в скане; плечо (fixed/volatility/full).
- Слайдеры + быстрые кнопки `25% / 50% / 100%` для доли депозита на сделку, с превью «при балансе X это ≈ $Y риска на сделку».
- Список стратегий (10 базовых + 6 профильных): статус, live win-rate/EV, значимость, состояние kill-switch.
- Автоисполнение vs подтверждение каждой сделки (`toggle_auto_exec`, таймаут подтверждения) — подтверждение приходит в приложение модальным окном с win-rate/EV и бэктестом.
- Обучение SAC: запуск, прогресс, откат модели (`rollback_sac`), бэктест, «значимость альфы», AI-isolation.

## 4. Motion-система (ключевое требование)

Пользователь должен **видеть, что происходит с монетами**, а не читать цифры. Вся анимация — на токенах из `shared/motion` (длительности, пружины, easing), 60 fps на мобильном WebView, только `transform/opacity`, обязателен `prefers-reduced-motion` (статичные замены) и режим «экономия батареи».
- **Radar монет:** живая сетка/орбита монет текущего скана. Монеты тянутся по воронке **Скан → Prescore → Сигнал → Guards → Позиция**; отсеянные «гаснут» с причиной при тапе; прошедшие «влетают» в слот позиции.
- **Тикеры:** цена с мягким flash зелёный/красный и анимированными цифрами (rolling digits); sparkline в каждой карточке.
- **Позиция «дышит»:** пульс по знаку PnL; полоса между SL и TP с бегущим маркером цены; срабатывание trailing — видимый «подтяг» линии SL.
- **События:** открытие — монета занимает слот с лёгким spring; закрытие в плюс — всплеск и подсчёт PnL, в минус — приглушённое затухание. Panic Close — отдельная последовательность (все карточки схлопываются).
- **Цифры и графики:** count-up PnL, плавная перерисовка heatmap, переходы вкладок через shared-layout (без «прыжков»).
- Haptics: Telegram `HapticFeedback` / нативные уведомления и звук в Tauri — на открытие/закрытие сделки, Panic, ошибки.
- Скелетоны вместо спиннеров; состояние «нет связи / бот не отвечает» (healthcheck > 120 с) — явный баннер и блокировка опасных кнопок.
