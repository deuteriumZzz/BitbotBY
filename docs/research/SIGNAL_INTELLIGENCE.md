# Signal Intelligence

Цель: понимать, на чём стоит каждое решение, не меняя confidence вслепую.

## Что есть
- **Единый контракт** (`backend/bitbot/domain/contracts.py`): `ModelOutput`, `TradingDecision` со статусом LONG / SHORT / NO_TRADE / INSUFFICIENT_DATA; у каждого confidence указана природа (`confidence_kind`): самооценка LLM, величина действия SAC, константа, скор стратегии, смесь.
- **Группы независимости** и **избыточные каналы** (`backend/bitbot/domain/signal_intelligence.py`): сколько независимых групп факторов за решением; где один фактор влияет несколькими путями. Разные группы ≠ доказанная независимость.
- **Конфликты политик** — объекты, а не среднее.
- **Цепочка confidence по стадиям** (`conf_trail`): как менялась уверенность на каждом шаге.
- **Отчёт по журналу**: `python -m bitbot.research.signal_intelligence_report` — стадии, избыточность, конфликты, отклонённые возможности, теневые стратегии объединения, теневой Risk Gate.

## Что намеренно НЕ сделано
Дедупликация confidence (C-1, C-2): она меняет торговые решения. Ворота: несколько сотен записей `conf_trail` → количественный отчёт, какие факторы стекаются → A/B на истории → согласование владельцем.

## Теневые стратегии объединения
`current` (эталон, совпадает с боевым `_hybrid` на 350 комбинациях), `agreement`, `weighted`, `contextual`, `risk_aware`. Ни одна не объявлена лучшей: для выбора нужны исходы после издержек.

## Исходы
Запись `outcome` связывает решение с результатом сделки по `decision_id`; на неё опираются аудит решения, RAG и будущая Meta-Model.
